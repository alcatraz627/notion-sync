## Session Insights

- **The killer insight (gotcha):** measuring diff noise by word-diff *segments* (`{+ +}`) is blind to whole blank-line add/removes, but the "remote changed" *classification* is driven by line-level add/remove (`hasMeaningfulDiff`). I optimized segments to −72% while the structural blank-line gap — the actual badge driver — sailed through. **Two different noise axes; always check which one the consumer (here: the badge) actually reads.**
- **Round-trip is not lossless:** for markdown↔Notion, base-vs-remote "changed" is almost always true (cosmetic deltas on every synced page). The useful signal isn't "differs from snapshot" but "differs *substantively*" → that's a classification/threshold question, NOT solvable by more normalization. Normalization shrinks per-file noise; classification decides what's worth surfacing. They're complementary; normalization is now maxed.
- **Symmetry safety property** (load-bearing, reused all session): `normalizeForDiff` runs identically on both sides before git-diff, so for any deterministic `f`, `a==b ⟹ f(a)==f(b)`. **No normalization rule can ever manufacture a false positive** — worst case it fails to collapse noise. This let me be aggressive (even on emphasis/code) without fear.
- **Frontmatter was a STALE BASE artifact**, not round-trip: base snapshots predate the docs gaining frontmatter (0/30 base had it, 30/30 local+remote did, identically). Stripping it is unambiguously safe (frontmatter never pushed).
